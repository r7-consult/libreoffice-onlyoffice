# Магазин плагинов для LibreOffice в виде дополнения: вариант «А+»

**Статус:** предложение; нужно решение о запуске короткой проверки  
**Дата:** 2026-11-26  
**Как читать:** раздел 1 — для руководства, без технических подробностей; разделы 2–13 — для архитекторов и разработчиков

## 1. Записка для руководства

### 1.1 О чём речь

**LibreOffice** — свободный офисный пакет (текстовый редактор, таблицы, презентации), который многие организации используют вместо Microsoft Office.

У редакторов **ONLYOFFICE** и совместимых с ними продуктов (по всей видимости, включая Р7-Офис — это нужно подтвердить) есть **магазин плагинов**. Плагины — небольшие дополнения к редактору: переводчики, проверка правописания, вставка схем и формул, ИИ-помощники, связь с корпоративными системами. В официальном каталоге ONLYOFFICE 62 плагина. Кроме того, есть плагины, которые заказчики сделали для себя, и наш продукт **«Слайдер Данные»**.

В LibreOffice таких плагинов нет, а собственные дополнения LibreOffice устроены совсем по-другому.

**Цель:** чтобы плагины ONLYOFFICE работали в LibreOffice **без переделки**, а «Слайдер Данные» работал в LibreOffice так же, как в Excel и Р7.

### 1.2 Два пути

**Путь 1 — собственная версия LibreOffice.** Мы берём исходный код LibreOffice, встраиваем поддержку плагинов внутрь и выпускаем свою сборку офисного пакета.

- Технически это самый полный вариант.
- Но мы становимся поставщиком офисного пакета. LibreOffice выходит дважды в год, плюс исправления безопасности. Каждое обновление нужно переносить в свою версию, проверять и выпускать заново. По оценке, на это постоянно уйдут **3–5 инженеров**.
- Пользователям придётся заменить привычный LibreOffice на нашу сборку.

**Путь 2 — «А+»: дополнение к обычному LibreOffice.** Оно ставится к уже установленному LibreOffice, как расширение к браузеру.

Раньше считалось, что дополнение может показать плагин только в отдельном окне рядом с LibreOffice, а это неудобно и не годится для большинства плагинов. Анализ исходного кода LibreOffice показал, что возможностей у дополнений больше: плагин можно показать **во встроенной боковой панели**, а его команды выполнять **внутри LibreOffice**. Это и есть вариант «А+».

### 1.3 Что даёт «А+»

- **Не нужна своя версия LibreOffice.** Дополнение работает с тем LibreOffice, который уже стоит у пользователей. Обновления LibreOffice ставятся как обычно.
- **Ниже постоянные расходы.** По оценке, **1–2 инженера** на поддержку совместимости вместо 3–5.
- **Проще распространение.** Пользователь устанавливает дополнение, а не меняет офисный пакет.
- **Плагины выглядят почти как в ONLYOFFICE:** в боковой панели, в отдельных окнах, в контекстном меню.

### 1.4 Чем придётся пожертвовать

Без небольших доработок самого LibreOffice часть возможностей будет недоступна:

1. **Самое важное.** Данные некоторых плагинов (например, вставленные схемы или ссылки на литературу) могут **теряться при сохранении файла в формате Word или Excel**. Такие плагины до доработки выпускать нельзя.
2. Плагины не смогут добавлять свои вкладки в «ленточный» интерфейс — только пункты в меню и на панелях инструментов.
3. Собственные функции для формул в таблицах, которые добавляют плагины, будут работать с ограничениями.
4. В части современных Linux-систем LibreOffice придётся запускать в режиме совместимости.
5. Подсказки плагинов рядом с курсором будут появляться не всегда точно в нужном месте.

Эти доработки небольшие. Их предлагается передать разработчикам LibreOffice, чтобы они вошли в официальные версии. До этого их можно поставлять отдельно тем заказчикам, которым они нужны сразу.

### 1.5 Что не меняется при любом пути

- **Основной объём работы одинаков.** Чтобы плагины ONLYOFFICE работали, LibreOffice должен понимать их команды — это тысячи операций с документом. «А+» экономит на сопровождении, а не на этой части.
- **Юридические ограничения одинаковы.** Код ONLYOFFICE нельзя копировать: всё пишется заново по их публичной документации. «ONLYOFFICE» — товарный знак: можно писать «совместимо с плагинами ONLYOFFICE», но нельзя использовать их бренд.
- **Требования безопасности одинаковы.** Сторонние плагины меняют документы пользователей, поэтому нужны проверка и подпись плагинов, возможность их отзыва и управление со стороны организации.

### 1.6 Что предлагается

Провести **короткую техническую проверку: 2–4 недели, 2–3 инженера.** На Windows, macOS и Linux нужно подтвердить:

- плагин показывается во встроенной панели и не перезапускается, когда пользователь переключается между панелями;
- команды плагина быстро меняют документ, и всё изменение отменяется одним нажатием «Отменить»;
- зависший плагин останавливается, а сбой плагина не закрывает LibreOffice;
- дополнение работает с двумя последними версиями LibreOffice без пересборки.

### 1.7 Как будет принято решение

| Итог проверки | Решение |

## 4. Архитектура «А+»

### 4.1 Компоненты

```text
LibreOffice (обычная сборка пользователя)
└── OXT «Plugin Host» (C++ UNO-компоненты, отдельный пакет под каждую ОС/архитектуру)
    ├── HostService (синглтон, UNO-служба)
    │   ├── PluginRegistry — установленные плагины, config.json, версии
    │   ├── Catalog & Policy — каталоги, подписи, отзыв, политики
    │   │   (настройки расширения через собственную схему конфигурации .xcs/.xcu)
    │   ├── ProtocolAdapter — сторона редактора протокола postMessage ONLYOFFICE
    │   │   + внедряемая среда выполнения плагина (написана с нуля)
    │   ├── EventBridge — опубликованные слушатели документа и представления
    │   └── CommandEngine — QuickJS-ng в составе OXT + Api на C++ поверх UNO
    ├── PanelFactory (XUIElementFactory) → PluginPanel (XToolPanel / XSidebarPanel)
    │   └── SystemChildWindow → WebHost (браузер, привязанный к дескриптору)
    ├── DialogHost — модальные и немодальные окна плагинов (окна верхнего уровня awt)
    ├── MenuInterceptor (XContextMenuInterceptor)
    ├── ToolbarManager — меню и панели инструментов плагинов
    │   (Addons.xcu + динамические панели инструментов через UI configuration API)
    ├── CalcAddIn — функции надстройки Calc для пользовательских функций
    └── WebHost (по платформам, раздел 5)
        └── процесс отрисовки на каждый плагин (свой origin)
```

### 4.2 Ключевой приём: состояние плагина живёт отдельно от окна панели

Боковая панель создаёт и уничтожает окна панелей при смене вкладки и контекста (риск Т-3). Поэтому:

- браузерный экземпляр плагина и его состояние принадлежат `HostService`, а не окну панели;
- `PluginPanel` при создании **подключает** готовый браузер к своему `SystemChildWindow` (смена родителя нативного окна), при уничтожении — **отключает** и прячет, не уничтожая;
- плагин получает события скрытия и показа, но не перезапускается.

Смена родителя поддерживается: у WebView2 есть `put_ParentWindow`, у `NSView` — перенос между родительскими представлениями, у X11 — `XReparentWindow` (для CEF — смена родителя окна браузера). Это нужно проверить в прототипе на всех ОС.

### 4.3 Выполнение команды

```text
плагин (процесс отрисовки)
  Asc.plugin.callCommand(fn) → postMessage {type:"command"}
      ▼
WebHost → ProtocolAdapter (главный поток LibreOffice, через очередь событий VCL)
      ▼
CommandEngine (контекст QuickJS этого плагина)
  XUndoManager.enterUndoContext → XModel.lockControllers
  → код плагина над Api (C++ → UNO напрямую, без рефлексии)
  → unlockControllers → leaveUndoContext → пересчёт (если isCalc)
      ▼
плагин: onCommandCallback (только JSON)
```

`Api` реализуется на **C++** с прямыми вызовами UNO. Привязка `jsuno` из ядра в «А+» недоступна (её нет в обычных сборках), а её рефлексивные вызовы всё равно медленные (риск Т-6). Бинарная совместимость C++-расширений с разными выпусками LibreOffice обеспечивается стабильным ABI URE для опубликованного API.

## 5. Встраивание браузера по платформам

| Платформа | Дескриптор от LibreOffice | Рекомендуемый движок | Интеграция цикла сообщений | Главные риски |
|---|---|---|---|---|
| Windows | HWND `SystemChildWindow` | **WebView2** (Chromium, есть в Windows 10/11) или CEF | WebView2 работает в цикле сообщений Win32 главного потока | Наличие и версия Evergreen Runtime в закрытых средах; DPI при смене монитора |
| macOS | `NSView*` | **WKWebView** | Работает в цикле Cocoa, который уже крутит LibreOffice | WebKit вместо Chromium (риск Т-2); CEF в чужом цикле Cocoa — сложная интеграция, не рекомендуется |
| Linux, X11 и XWayland, VCL-плагин gtk3 | XID `SystemChildWindow` | **CEF** в оконном режиме с родительским XID | Многопоточный цикл сообщений CEF; вызовы в LibreOffice — через очередь главного потока | Конфликт GTK: если LibreOffice работает с gtk4, а CEF подгружает gtk3 для своих диалогов, — столкновение символов; tdf#139609 (разработчики LibreOffice не хотят выдавать XID) |
| Linux, native Wayland | Нет | — | — | Без доработки ядра не работает; обходной путь — запуск LibreOffice через XWayland (`GDK_BACKEND=x11`) |
| Linux, VCL-плагины qt5/qt6/kf | XID под X11 — **не проверено** | CEF | Как для gtk3 | Нужна проверка в прототипе |

**Предлагаемый выбор для первого выпуска:** WebView2 (Windows) + WKWebView (macOS) + CEF (Linux X11/XWayland). Если прогон эталонного набора на WKWebView даст много отказов (П-6), рассмотреть CEF на macOS как отдельный технический риск.

### 5.1 Можно ли использовать Tauri

Проверено 2026-11-26 по исходникам `tauri-apps/wry` на GitHub (ветка `dev`, версия 0.58.1 в `Cargo.toml`; с опубликованной на crates.io версией не сверялось, docs.rs через прокси недоступен).

**Tauri целиком — нет.** Tauri — каркас самостоятельного приложения: он владеет процессом, главным циклом событий (`tao`), окнами и своим IPC. В «А+» процессом и циклом событий владеет LibreOffice; второй главный цикл в одном процессе невозможен, а окно Tauri не может стать дочерним окном панели LibreOffice. Tauri целиком применим только как отдельный процесс (вариант А) и, возможно, как внешняя служба SliderQuery для Proxy и больших данных (ADR-008), но не для интерфейса плагинов.

**Библиотека отображения Tauri — wry — да, это сильный кандидат на роль `WebHost`:**

| Возможность wry | Значение для «А+» |
|---|---|
| `WebViewBuilder::build_as_child` — веб-представление внутри существующего окна; Windows, macOS, Linux (только X11) | Совпадает с дескрипторами, которые отдаёт `getWindowHandle()`: HWND, `NSView`, XID |
| `build_gtk` — встраивание в GTK-контейнер внутри процесса (рекомендуется с `gtk::Fixed`); работает и под X11, и под Wayland | В gtk3-оболочке LibreOffice окно `SystemChildWindow` внутри является GTK-виджетом (`SystemEnvData::pWidget`), но через опубликованный API не выдаётся. После доработки **К-6** wry даёт native Wayland без XWayland |
| `with_custom_protocol` — свой протокол; страницы получают отдельный origin (`<scheme>://…` в macOS/Linux, `http://<scheme>.…` в Windows) | Отдельный origin на плагин (OO-SEC-1) |
| `with_ipc_handler` — сообщения из JavaScript (`window.ipc.postMessage`) в хост | Канал `ProtocolAdapter` (OO-RT); проверка источника (OO-RT-5) |
| `with_navigation_handler` — разрешение или запрет навигации | Запрет произвольной навигации (OO-SEC-6) |
| `WebContext` / каталог данных / `with_data_store_identifier` (macOS) | Раздельное хранилище на плагин (OO-SEC-1) |
| Единый API поверх WebView2, WKWebView, WebKitGTK | Одна реализация встраивания вместо трёх |

**Ограничения wry:**

1. **Только системные движки.** WebView2, WKWebView, WebKitGTK; CEF не поддерживается. Если для Linux понадобится совместимость уровня Chromium (риск Т-2), wry там не поможет.
2. **Linux: GTK 3 и WebKitGTK 4.1** (`gtk` 0.19, `webkit2gtk` 3.x). Нужен инициализированный GTK и работающий цикл GTK.
   - Оболочка gtk3: GTK уже инициализирован и цикл работает — совместимо.
   - Оболочка gtk4: GTK 3 и GTK 4 нельзя загрузить в один процесс — **несовместимо**.
   - Оболочки qt5/qt6/kf: пришлось бы вызывать `gtk::init` и прокручивать `gtk::main_iteration_do` из цикла LibreOffice — хрупко, не рекомендуется.
3. **Rust внутри процесса `soffice`.** Нужна прослойка `cdylib` с C-интерфейсом для C++-компонента. Все паники Rust перехватываются на границе (`catch_unwind`), иначе они роняют LibreOffice. В сборке расширения появляется Rust (для ветки `dev` — `rust-version = "1.92"`).
4. **Не проверено:** обязательно ли создавать веб-представление в главном потоке и как wry ведёт себя при смене родительского окна (раздел 4.2).

В исходниках LibreOffice есть экспериментальная привязка UNO для Rust (`rust_uno/`, `--enable-rust-uno`, пример расширения). В обычных сборках её нет, поэтому основной код «А+» остаётся на C++, а wry подключается через C-интерфейс.

**Рекомендация по `WebHost`:**

| Платформа | Реализация |
|---|---|
| Windows, macOS | wry (`build_as_child`) вместо собственного встраивания WebView2 и WKWebView |
| Linux, оболочка gtk3 | wry на WebKitGTK, если прогон эталонного набора на WebKit (П-6) даёт приемлемую долю отказов; иначе CEF |
| Linux, оболочки gtk4 и Qt | CEF; либо native-решение после доработки К-6 |
| Tauri целиком | Не для плагинов; только для внешней службы SliderQuery, если она останется |

## 7. Что «А+» требует от пользовательской среды

- LibreOffice не старше выбранной минимальной версии (например, две последние поддерживаемые ветки; проверяется прототипом).
- Linux: сеанс X11 или запуск LibreOffice через XWayland, пока нет доработки **К-6**.
- Windows: Microsoft Edge WebView2 Runtime (обычно уже установлен; в закрытых средах — офлайн-установщик в составе дистрибутива).
- Распакованный размер расширения: Windows — небольшой (WebView2 системный); macOS — небольшой; Linux — +150–200 МБ за счёт CEF.

## 9. Упаковка и распространение

- **Отдельный OXT на каждую ОС и архитектуру** (Windows x64/arm64, macOS x64/arm64, Linux x64), с платформенными метаданными в `description.xml`. Это согласуется с выводом исходного проекта против универсального OXT (§П2.25.2).
- **Установка:** для пользователя через менеджер расширений или `unopkg`; для организации — общая установка средствами развёртывания LibreOffice.
- **CEF на Linux:** как отдельный пакет в каталоге расширения или системный пакет дистрибутива; путь задаётся в конфигурации расширения.
- **Подписание:** нативные библиотеки подписываются средствами ОС (Authenticode, подпись и нотаризация Apple); сам OXT — подписью каталога магазина.
- **Обновление:** через механизм обновлений расширений LibreOffice (`description.xml` → update information) или через собственный магазин.
- **Совместимость:** расширение проверяет версию LibreOffice при запуске и отключает недоступные возможности через согласование возможностей (§П2.13.4), а не падает.

## 11. Прототип П-1

**Цель:** подтвердить или опровергнуть, что «А+» закрывает ключевые требования без собственной сборки.

**Состав (2–4 недели, 2–3 инженера):**

1. OXT на C++: панель боковой панели для Writer и Calc, внутри — `SystemChildWindow` с браузером (WebView2 в Windows, WKWebView в macOS, CEF в Linux X11/XWayland). Для той же панели — вариант на wry (раздел 5.1) с сравнением: объём кода, смена родителя окна, поведение при падении процесса отрисовки, работа с оболочкой gtk3.
2. Минимальный `ProtocolAdapter` и внедряемая среда: рукопожатие `initialize` → `plugin_init` → `init`, методы `executeMethod("GetSelectedText")` и `executeMethod("PasteText")`.
3. Встроенный QuickJS-ng и 10 методов `Api` на C++: `Api.GetActiveSheet`, `ApiWorksheet.GetRange`, `ApiRange.SetValue` (включая двумерный массив), `Api.GetDocument`, `ApiDocument.GetElement`, `ApiParagraph.AddText` и т. п.; сторожевой таймер.
4. Перехват контекстного меню с одним пунктом от плагина.
5. Один плагин-пример ONLYOFFICE без изменений (например, «Hello world» из `sdkjs-plugins`) и один плагин каталога (например, `wordscounter` или `translator` с заглушкой сервиса).

**Критерии выхода (все обязательны для выбора «А+»):**

| № | Критерий |
|---|---|
| 1 | Плагин отображается в панели на Windows, macOS и Linux (X11 и XWayland) |
| 2 | Переключение вкладок боковой панели, смена контекста (выделение в Writer), открепление панели — без перезапуска плагина |
| 3 | `callCommand`, записывающий 10 000 ячеек через `ApiRange.SetValue` с двумерным массивом, выполняется ≤ 1 с и отменяется одним действием Undo |
| 4 | Бесконечный цикл в команде прерывается сторожевым таймером, LibreOffice остаётся работоспособным |
| 5 | Падение процесса браузера не роняет LibreOffice, плагин перезапускается из панели |
| 6 | Расширение устанавливается и работает на двух выбранных выпусках LibreOffice без пересборки |
| 7 | Пункт плагина в контекстном меню появляется без заметной задержки (≤ 300 мс) |
| 8 | На Linux нет конфликтов GTK при работе LibreOffice с VCL-плагином gtk3 (gtk4 — измерить и задокументировать) |

**Дополнительно измерить:** память на панель, холодный старт плагина, поведение при высоком DPI, IME (китайский ввод), доступность содержимого панели для экранного диктора.

## 12. Как выбирать между «А+» и Б

| Результат П-1 | Решение |
|---|---|
| Все критерии выполнены | **«А+»**; доработки ядра К-1…К-3 — отдельными изменениями, предлагаемыми в основной проект |
| Не выполнены только критерии Linux (1 для Linux, 8) | «А+» для Windows и macOS; для Linux — доработка К-6 или временная заплатка VCL |
| Не выполнены 2 или 5 (жизненный цикл, изоляция) | Повторный прототип с отдельным процессом браузера; если не помогло — Б |
| Не выполнены 3 или 4 (движок команд) | Это общая проблема, не специфичная для «А+»: пересмотреть ADR-004 и ADR-005 для всех вариантов |
| Не выполнен 6 (совместимость с выпусками) | Б или поставка «А+» только для одной зафиксированной версии LibreOffice |
