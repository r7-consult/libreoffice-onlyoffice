## Decision

**Outbound licence: GNU AGPL-3.0, strict, decided by the user on 2026-11-28.** The project and everything it
distributes is licensed under AGPL-3.0 alone. Our notices do not offer "or later". `LICENSE` in the repository is the
standard AGPL-3.0 text.

What this means, as our reading (counsel must confirm, see open points):
- **Inbound inputs are compatible with AGPL-3.0**: MPL-2.0 names the AGPL among its secondary licences; Apache-2.0
  and GPL-3.0 parts are compatible with AGPL-3.0; MIT and BSD-style licences are permissive. We copy no LGPL-only code.
  Each input keeps its own copyright and notice.
- **Network clause (AGPL section 13)**: anyone who interacts with a modified version over a network must be offered its
  source. Relevant if the host ever runs plugin code for remote users.
- **Products built on this must also be AGPL-3.0.** A plugin or extension that embeds this code cannot be
  distributed under permissive terms.
- **ONLYOFFICE Additional Terms are not adopted.** The copy of AGPL-3.0 in the ONLYOFFICE repositories ends with
  "Additional Terms" (attribution, interface notices, trademarks). Those belong to ONLYOFFICE's program. We use the
  standard text only.

Earlier decision, still in force for the inputs:

1. The project's licence follows its inputs. Anything derived from an AGPL-3.0 source (inventory signatures, read/edit
   classification, expectations generated from Document Builder) is treated as AGPL-3.0 derived.
2. Apache-2.0 and MPL-2.0 inputs keep their own notices. Their notice files travel with any distributed build.
3. Names and signatures are facts, but the project treats the AGPL-derived inventory as inherited, not as an
   exception.
4. Plugin code written in this repository is licensed as the repository's `LICENSE` file says. That file must be
   chosen to be compatible with every input above; see the open points.

## Open points (for counsel)

1. **Combined licence: outbound chosen (AGPL-3.0). Counsel to confirm** that each input listed above may be combined
   into an AGPL-3.0 work, and that the LibreOffice NOTICE and per-file headers are preserved.
2. **AGPL network clause.** AGPL-3.0 requires offering source to users who interact with the software over a network.
   Relevant if the host ever serves plugin code remotely.
3. **Expectations as data.** The expected-result files are generated by running Document Builder. Whether they count as
   output of an AGPL program, and so inherit its licence, is a question for counsel. Under this decision they inherit it.
4. **Running Document Builder.** Running it on the team's machine to make expectations is not distributing it. Shipping
   it, or a copy of its binaries, would be distribution and is out of scope.
5. **Notices.** QuickJS-ng (MIT) and WebView2 (BSD-style) require their notices to travel with any distributed build.
   WebView2 also ships a `NOTICE.txt`, which must be included.

## What changes in the repository

- `LICENSE` is the standard AGPL-3.0 text. It was taken from the first 661 lines of the AGPL copy in the
  ONLYOFFICE DocumentBuilder repository, which stop before ONLYOFFICE's "Additional Terms". A direct download from
  gnu.org was blocked by the network proxy here, so counsel should compare `LICENSE` with
  <https://www.gnu.org/licenses/agpl-3.0.txt> before the first release.
- Each generated inventory or expectation file records its source licence in the first comment or header line
  where the format allows it.
